# Hotfix: Rex Engine Resilience - 2026-03-05

## Root Cause Summary

**Problem 1: Import Extension Configuration**
- Import extensions needed verification for `ts-node --esm` runtime
- With `"type": "module"` in package.json, ts-node --esm requires `.ts` extensions
- This differs from standard TypeScript compilation guidelines (which suggest `.js`)
- Resolution: Verified all imports correctly use `.ts` extensions

**Problem 2: Fragile LLM JSON Parsing**
- Single-attempt parsing with no error recovery
- LLM responses occasionally malformed or wrapped in markdown
- No validation of required fields before delivery
- Result: JSON parse errors, pipeline failure

**Problem 3: Delivery Logic Gaps**
- Mobile delivery attempted even when email failed
- Should have failed hard on synthesis failure (already correct)
- Needed explicit gating: email success → mobile delivery

### B. Resilient JSON Parsing

**New Functions in `rex-engine.ts`:**

1. **`extractJsonFromResponse(content: string)`**
   - Tries direct `JSON.parse()` first
   - Falls back to markdown code block extraction: `` ```json ... ``` ``
   - Falls back to brace-delimited extraction: `{...}` with noise
   - Throws descriptive error if all strategies fail

2. **`validateLlmResponse(parsed: any)`**
   - Validates `email_body` field exists and is string type
   - Enforces minimum length (50 chars) to catch truncated responses
   - Throws specific error messages for debugging

3. **`callLlmApi(prompt: string, attemptNum: number)`**
   - Separated API call logic for retry orchestration
   - Logs attempt number for debugging
   - Checks HTTP status codes

4. **`synthesize()` - Enhanced with Retry Logic**
   - **3 retry attempts** with exponential backoff (1s, 2s, 3s)
   - Each attempt: call API → extract JSON → validate fields
   - Fails hard after all retries exhausted
   - Detailed error logging for each failed attempt

### C. Delivery Logic Hardening

**File: `rex-engine.ts` (main function)**

```typescript
// Step 5: Deliver email first
status.email = deliverEmail(emailSubject, emailBody);

// Only proceed to mobile if email succeeded
if (status.email.ok) {
  console.log('\n📱 Email succeeded, proceeding to mobile delivery...');

  const whatsappStatus = runOpenclawMessage('whatsapp', ...);
  const telegramStatus = runOpenclawMessage('telegram', ...);

  status.mobile = { whatsapp: whatsappStatus, telegram: telegramStatus };
} else {
  console.error('\n❌ Email delivery failed, skipping mobile delivery.');
  status.mobile = {
    whatsapp: { ok: false, error: 'Skipped due to email failure' },
    telegram: { ok: false, error: 'Skipped due to email failure' },
  };
}
```

**Key Behaviors:**
- ✅ Synthesis succeeds + email succeeds → send mobile
- ❌ Synthesis fails → fail hard, no delivery
- ❌ Email fails → skip mobile, fail hard
- Status JSON always written with definitive failure reasons
